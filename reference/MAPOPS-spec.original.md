# MAP OPS — 구현 명세서 (Claude Code 전달용)

## 0. 읽는 법

- 이 문서는 대화로 반복 설계·수정해 온 프로토타입을 정식 프로젝트로 재구현하기 위한 명세다.
- 첨부 `map-ops.html`(단일 파일, 순수 JS, 약 1,100줄)은 **동작하는 참고 구현**이다. 동작과 UX의 기준이지, 코드 구조의 기준은 아니다. 명세와 충돌하면 명세가 우선이며, §6의 결함은 그대로 이식하지 말 것.
- 불명확한 점은 §7의 질문을 사용자에게 먼저 한다.
- UI 문구는 한국어이며 기존 어조(하오체: "~하시오", "~하오")를 유지한다. 사용자가 원하는 톤이다.
- 구현은 §9의 마일스톤 단위로 나눠 진행하고, 좌표 변환 수식(§3)은 단위 테스트를 먼저 작성한다.

## 1. 목적

다층 구조 게임(레인보우 식스 시즈 등)의 맵을 보는 **개인용** 도구.
참고 사이트(r6maps)가 신규 맵을 갱신하지 않으므로, 사용자가 직접 단면도 이미지를 올려 맵을 추가하고 r6maps와 같은 방식으로 쓰는 것이 목표다.

핵심 가치: **한 층에서 가리킨 지점이 다른 층의 같은 물리적 위치에 즉시 대응되어 보인다.**

사용자가 정의한 흐름은 3단계이며, ②와 ③은 화면·모드 모두 명확히 분리되어야 한다.

1. 맵 파일 업로드
2. 층 정렬 및 배율 조정 (맵당 1회성 보정)
3. 사용 (마커 등록, 동일 xy 확인)

## 2. 참고자료

- r6maps 오픈소스: `github.com/capajon/r6maps` (MIT). 파악한 범위의 구조:
  - 층마다 `top`/`left` 오프셋이 있고, 모든 층이 하나의 좌표 공간에 정렬된다.
  - 포인트는 층 번호 + 절대 `top`/`left`. 층간 연결(사다리 등)은 같은 좌표를 다른 층 번호로 반복하고 `otherFloor`로 표시한다.
  - 지하 배경층은 이미지 크기가 달라(2560×1440 vs 1175×1032) 별도 오프셋을 쓴다.
  - 파일: `dev/js/main/` 아래 `main.map-data.js`(약 3,200줄), `main.map-render.js`, `main.controls.js`, `main.drawing.js`, `main.sessions.js`, `main.select-maps.js`. **drawing/sessions의 내용은 아직 읽지 않았다.** 필요하면 직접 읽고 참고할 것.
- 코드를 가져다 쓰면 MIT 고지를 유지한다. **이미지는 별개 권리**(Ubisoft 소스를 가공한 것)이므로 앱에 번들하지 않는다. 사용자가 본인 이미지를 올린다.
- r6maps.com은 robots.txt로 자동 접근을 막고 있다. 사이트 스크래핑은 하지 말고 저장소만 참조한다.

## 3. 데이터 모델과 좌표 수학

### 3.1 엔티티

```
Map     { id, name, anchorFloorId, floors[], markers[] }
Floor   { id, name, imageRef, rel: { d:(dx,dy), r } }   // 기준층은 rel 없음(항등)
Marker  { id, x, y, type, label, floorIds[] }           // 월드 좌표
type    ∈ objective(목표) | camera(카메라) | connector(층간연결) | note(메모)
```

- 마커 유형·색: 목표 `#e0a83e`, 카메라 `#3ea6ff`, 층간연결 `#e0555a`, 메모 `#8b96a5`.
- `connector`는 여러 층(`floorIds`)에 같은 좌표로 표시된다. 나머지는 단일 층.

### 3.2 좌표계

- **월드 좌표 = 기준층 로컬 좌표.** 마커는 월드 좌표로 저장한다.
- 각 층 *i*는 닮음변환(균일 스케일 + 평행이동) `T_i(p) = s_i·p + t_i`로 월드에 놓인다. *p*는 그 층 이미지의 픽셀 좌표(좌상단 원점).
- 별도로 **뷰 변환** `screen = z·world + pan`이 있다 (사용 화면의 줌/팬). 층 보정과 뷰 변환은 서로 독립이다.

### 3.3 기준층 방식(star topology) — 사용자가 확정한 설계

- 사용자가 **기준층 1개를 지정**한다. 나머지 층(종속층)은 이전 층이 아니라 **기준층을 직접 기준으로** 정렬한다 (오차 누적 방지, 한 층 조정이 다른 종속층에 영향 없음).
- 보정 중에는 기준층도 자유롭게 이동/확대할 수 있고, 그러면 **종속층 전체가 강체로 함께 움직여야 한다.** 사용자는 이것으로 "전체가 제대로 물려 있는지" 확인한다.
- 종속층의 상대 변환 `(r_i, d_i)`는 **기준층 로컬 좌표**로 저장한다.

  ```
  s_i = s_A · r_i
  t_i = t_A + s_A · d_i
  ```

- 드래그(월드 이동량 Δ): `d_i += Δ / s_A`
- 커서 *c*(월드 좌표) 고정 휠 줌: 

  ```
  s_i' = clamp(s_i · f)               // f = 1.08 또는 1/1.08, 범위 0.3~3
  t_i' = c − (c − t_i) · (s_i'/s_i)
  r_i  = s_i' / s_A
  d_i  = (t_i' − t_A) / s_A
  ```

- **저장 시 정규화:** 기준층 변환을 항등 `(s_A=1, t_A=0)`으로 굽는다. 저장되는 것은 상대 변환뿐이며, 이후 월드 좌표가 흔들리지 않으므로 마커 좌표와 항상 일치한다.

### 3.4 뷰 변환 (사용 화면)

- 휠 줌: 커서 아래의 월드 점을 고정한다. 범위 0.5~6배, 배율 1.15 / (1/1.15).
- 드래그 팬. 클릭과 드래그는 **4px 임계값**으로 구분한다.
- 층을 전환해도 뷰 변환은 유지된다. 사용자 설명: 공식 맵 면적을 100%라 하면 실제 게임 사용 영역은 약 40%라서, 한 번 확대해 두면 층을 오가도 그 영역만 보여야 한다.

## 4. 화면 요구사항

### 4.1 맵 선택

- 카드 그리드(썸네일=첫 층, 이름, "N개 층 · 마커 M개"). **그리드 마지막 칸(우하단)에 점선 "+ 맵 추가" 카드.**
- 상단바: "← 맵 목록", 동기화 버튼/상태 표시(§4.5), 마법사 중에는 "✕ 마법사 나가기".

### 4.2 사용 화면 (뷰어)

- **층 탭**, "이전 층 겹쳐보기"(반투명, 단일 보기에서만).
- **2단 비교:** 좌우 패널, 각자 층 선택 드롭다운. **줌/팬은 한쪽을 조작하면 다른 쪽에 같은 값이 복사된다** (층 이미지는 각자 다르게 보이되 확대·이동 관점은 동일).
- **좌클릭(드래그 없음) = 위치 확인(probe).**
  - 클릭 지점에 **십자선(+)** 이 표시된다. 동그라미 없음. 렌더 중인 **모든 패널**에 같은 월드 좌표로 표시된다.
  - 화면 하단에 "선택 위치" 바: `[N층에서 보기]`(다른 층 각각) · `[+ 여기에 마커 추가]` · `[⚙]` · `[닫기]`.
  - `N층에서 보기`는 그 패널의 층을 바꾸며 십자선은 같은 월드 좌표에 남는다. (2단 비교에서는 다른 쪽 패널에 이미 같이 보이므로 이동이 필요 없다.)
- **좌클릭 드래그 = 화면 이동(팬).** 마커 생성은 클릭으로 즉시 되지 **않고**, 반드시 `+ 여기에 마커 추가` → 작은 폼(유형, 이름, 층간연결이면 연결 층 체크박스)을 거친다.
- **마커 hover:** 마우스를 올리는 동안만 그 마커 좌표에 십자선이 렌더 중인 모든 패널에 표시되고, 벗어나면 사라진다(이미 클릭으로 고정된 십자선이 있으면 그 위치로 복귀). 마커 클릭은 그 좌표를 probe로 고정한다. 등록된 마커 **모든 유형**에 적용한다.
- **십자선 설정(⚙):** 길이(10~50px), 굵기(1~6px), 색상. 슬라이더 조작 중 실시간 반영(전체 재렌더 금지, §8).
- 사이드바(단일 보기): 현재 층 마커 목록 + 삭제.
- 마커 점 위 mousedown, 폼, 하단 바 위 mousedown은 팬을 시작하지 않는다.

### 4.3 맵 추가 마법사 — **전체 페이지**(모달/팝업 아님)

작은 팝업은 정보량이 부족하다는 사용자 피드백으로 전체 페이지로 확정했다.

**1단계 — 이름**

**2단계 — 층 업로드**

- 층 행: `⠿`(드래그 핸들, HTML5 DnD로 순서 변경) · `★/☆`(기준층 지정, 지정된 행은 테두리 강조) · 썸네일 · 이름 입력 · 이미지 업로드/변경 · 삭제.
- `+ 층 추가`, `+ 여러 이미지 한번에 추가`: 파일 선택창에서 Ctrl/Shift로 여러 장을 고르면 **선택 순서대로 층이 자동 생성**된다.
- 삭제는 최소 1개 층을 남긴다. 기준층을 지우면 다른 층이 새 기준층이 되며, 현재 시각적 배치는 유지한다(상대 변환 재계산 후 제거).
- 기준층을 바꿀 때도 현재 시각적 배치는 유지한다(모든 층의 상대 변환을 새 기준 기준으로 재계산).
- 층이 1개뿐이면 3단계를 건너뛰며 **버튼 라벨이 처음부터 "완료 · 맵 저장"** 이어야 한다.

**3단계 — 정렬/배율** (종속층마다 반복)

| 서브 단계 | 대상 | 허용 조작 |
|---|---|---|
| 3-0 기준층 | 기준층 | 드래그 + 휠 (자유). 나머지 전체가 강체로 따라 움직임 |
| 3-1 위치 | 종속층 | **드래그만.** 휠 비활성. 기준층은 40% 불투명도로 아래에 깔림 |
| 3-2 배율 | 종속층 | **휠 + 드래그 모두.** (배율 변경 후 위치 미세 조정을 위해) |

- 사용자 요구: 위치와 배율을 동시에 만지면 정렬이 까다로우므로 **위치 먼저, 배율은 그다음.** 단 3-2에서는 드래그도 허용한다.
- 순서: 3-0 → (종속층 1: 3-1 → 3-2) → (종속층 2: 3-1 → 3-2) → … → 저장. 이전/다음 버튼으로 앞뒤 이동하며, 첫 종속층의 3-1에서 "이전"은 3-0으로 간다.
- 서브 단계마다 현재 스케일 %를 표시한다. "위치/크기 초기화" 버튼(종속층: 기준층과 겹침 상태로, 기준층: 항등으로).
- **전체 층 비교 격자**(기본 켜짐, 토글 가능):
  - **등록된 모든 층**을 2열 격자로 표시한다. 현재 조정 중인 층까지만 자르면 뒤쪽 층이 안 보이니 금지.
  - 모든 칸이 **동일한 프레임**(같은 확대율·중심)으로 그려지고, 같은 물리적 지점이 각 칸의 같은 자리에 있으면 정렬이 맞은 것이다. 기준층 칸에 ★ 표시.
  - 프레임(전체 bounding box를 칸에 맞추는 균일 배율 ×0.92, 중앙 정렬)은 **격자 화면 진입 시 1회만 계산해 고정**한다. 드래그/휠 중에는 재계산하지 않는다(§8). 층이 칸 밖으로 벗어나면 `↻ 격자 화면 재조정` 버튼으로 다시 계산.
  - 드래그/휠 중 실시간 갱신.
- 저장하면 맵이 목록에 추가되고 해당 맵의 사용 화면으로 진입한다.

### 4.4 맵 편집 (미구현, 필요)

프로토타입은 저장 후 층 순서·이름·재보정·삭제를 바꿀 수 없다. 마법사를 재사용하는 **편집 모드**가 필요하다. 이때 마커 좌표가 어긋나지 않도록 §3.3의 정규화 규칙을 지킨다.

### 4.5 공유/동기화

- 요구: 다른 사람과 맵 데이터를 공유하고, 한쪽이 바꾸면 다른 쪽에 (준)실시간으로 반영된다.
- 프로토타입은 Claude 아티팩트 전용 `window.storage`(shared=true) 키 하나에 전체 JSON을 쓰고, 맵 목록 화면에서만 5초 폴링했다. **이 방식은 이식 불가능하다.** §7의 결정이 필요하다.

## 6. 프로토타입의 결함 — 재구현에서 반드시 고칠 것

1. **캔버스가 480×300 고정 + `object-fit: cover`** → 이미지 비율이 왜곡/잘림. 원본 해상도·비율을 유지하고 월드 단위를 정의할 것.
2. **기준층 변환 수식 오류.** 프로토타입은 `t_i = t_A + d_i`(s_A를 곱하지 않음)이다. 기준층을 *확대*하면 종속층이 강체로 따라오지 않는다(평행이동만 정확). §3.3 수식으로 교체하고 단위 테스트로 보장할 것. (프로토타입의 3-0은 이동만 정확하고 줌은 부정확하다.)
3. **`anchorFloorId`가 저장되지 않는다.** (`rel*` 값만 층 객체에 남는다.)
4. **마커 좌표계:** 현재는 보정 후에만 마커를 만들어 문제가 드러나지 않았지만, 편집 모드를 넣으면 층이 움직일 때 마커가 어긋난다. §3.3 정규화 + 월드=기준층 로컬로 고정.
5. 저장된 맵 편집 불가(§4.4).
6. **마법사 시작 시 빈 "1층" 행이 남는다.** 다중 업로드를 하면 쓸모없는 검은 층이 생겨 사용자가 직접 지웠다. 빈 플레이스홀더는 업로드 시 채우거나 대체할 것.
7. **층 이름 자동 부여가 위치/내용과 무관**(`N층`)해서 순서를 바꾸면 "4층 기준으로 2층을 맞추는 중" 같은 헷갈리는 문구가 나왔다. 파일명을 기본 이름으로 쓰고, 순서 변경 시 자동 번호 이름만 재부여하는 옵션을 고려할 것.
8. 이미지를 base64로 JSON 한 키에 몰아 저장 → 용량 한계. 이미지는 파일/Blob으로 분리.
9. 마커 이동·수정 불가(삭제만 가능).
10. 전체 DOM을 매번 다시 만드는 렌더링 → 상태 기반 렌더링(컴포넌트 또는 최소 diff)으로.

## 7. 사용자에게 먼저 확인할 미결정 사항

1. **공유 방식:** 개인 로컬 전용(IndexedDB + JSON 내보내기/가져오기)인가, 여러 사람이 쓰는 서버(REST + WebSocket/SSE, 이미지는 파일 저장)인가?
2. **배포 형태:** 순수 웹앱 / 데스크톱(Electron·Tauri)?
3. **"c+휠"의 의미:** 사용자가 "c+휠로 배율 조정"이라고 썼다. 현재는 수정키 없는 휠이 줌이다. Ctrl+휠을 의도했는지 확인(브라우저 기본 줌과 충돌하므로 `preventDefault` 필요).
4. **저장된 맵 편집 범위**(층 순서·이름·재보정·이미지 교체 중 무엇까지).
5. **마커 유형 확장 여부:** r6maps에는 카메라 시야 이미지, 해치/사다리 전용 아이콘, 그리기 도구, 세션 공유 등이 있다. 지금 구현은 4종 단순 마커뿐이다.
6. 기술 스택 선호(미지정 시 제안: Vite + TypeScript, 필요 시 React). 서버가 필요하면 Node + SQLite + 파일 저장소.

## 8. 구현 교훈 — 실제로 겪은 버그

- **연속 입력(슬라이더·드래그·휠) 중 전체 재렌더 금지.** 슬라이더 요소가 교체되어 드래그가 끊겼다. 변경된 요소 스타일만 직접 갱신.
- **hover로 DOM을 재생성하지 말 것.** 포인터 아래 요소가 교체되면 mouseenter/leave 깜빡임 루프 위험이 있다. 십자선은 상시 존재하는 요소를 표시/위치만 바꾼다.
- **비교 격자의 프레임을 매 프레임 재계산하면** 한 층만 움직여도 모든 칸의 기준이 흔들려 "엉뚱한 층(4층)만 움직인다"고 오인했다. 진입 시 1회 계산·고정.
- 비교 격자는 항상 모든 층을 그릴 것. 현재 인덱스까지 자르면 앞 층을 조정할 때 뒤 층이 연쇄로 따라오는지 확인할 방법이 없다.
- 기준을 "이전 층 대비 상대값" 연쇄로 두면 앞 층 조정이 뒤 층에 번지거나 오차가 누적된다. 기준층 직접 방식(§3.3)이 정답으로 확정되었다.
- 분할 뷰 줌/팬 동기화는 값 복사 + 반대 패널 DOM 직접 갱신.
- 마법사가 모달이면 정렬 화면이 너무 작았다. 전체 페이지로.
- 층이 1개일 때 저장 버튼이 "다음"으로 표시되어 "완료 버튼이 안 보인다"는 혼란이 있었다.
- 입력창이 든 행 전체를 `draggable`로 두면 입력창 안 드래그와 충돌할 수 있다. 핸들에만 드래그를 거는 방식도 검토.

## 9. 권장 마일스톤

1. **M1** 프로젝트 뼈대, 데이터 모델, 닮음변환 모듈 + **단위 테스트** (기준층 s_A≠1에서의 강체성, 커서 고정 줌, 저장 시 정규화 전후 월드 좌표 불변).
2. **M2** 맵 선택 화면 + 영속화(§7-1 결정 반영).
3. **M3** 마법사 1~2단계 (다중 업로드, DnD, ★ 기준층).
4. **M4** 마법사 3단계 (3-0/3-1/3-2, 비교 격자).
5. **M5** 사용 화면 (뷰 변환, probe, 마커, hover, 십자선 설정, 2단 비교 동기화).
6. **M6** 공유/동기화.
7. **M7** 맵 편집 모드, 마커 이동/수정.
